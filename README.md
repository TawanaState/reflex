# Project Reflex

**Experimental diffusion-model runtime for short tool decisions and conditional generation.** Built by Tawananyasha Mukoriwo on an NVIDIA DGX Spark. This is a research prototype; see [RESULTS.md](RESULTS.md) for the evidence and limitations.

## How it works

Reflex serves Google's DiffusionGemma 26B-A4B-it through `/v1/chat/completions`. A short masked canvas scores candidate tool tokens over a cached prompt. The selected schema determines the current compute path: one pass for a no-argument tool; a strict explicit-number extractor for the narrow case of one required numeric argument; or a larger canvas for free-text generation. The present automatic exit threshold is a **0.90 heuristic, not a calibrated error guarantee**. Prompt KV reuse is part of DiffusionGemma's underlying architecture.

| Path | Current implementation | What still needs proof |
| --- | --- | --- |
| Atomic | One decoder pass after prefill | Generalization beyond the local routing subset and useful calibrated coverage. |
| Primitive | Learned tool choice plus deterministic extraction of one explicit valid number; ambiguous requests abstain | Learned argument synthesis and broader schema coverage. |
| Generative | Larger multi-pass canvas, reusing prompt KV; invalid tool payloads are withheld | Valid required arguments and quality against the official diffusion sampler. |

## Evidence status

The v1 model ran on the GB10, but its training data was flawed: BoolQ used IDs that encode unrelated tokens in the installed tokenizer, and all BFCL labels were set to option zero. Its saved held-out Step-1 result is **43/100 correct**: 43/75 BoolQ and 0/25 Banking77. Its reported calibrated policy exited on **0/100 test items**, so “0% error on exits” demonstrated no useful fast path. The old Tier-2 artifact reports **20%** exact numeric argument accuracy. Live v1 calls selected `mute_audio {}` for volume and email requests.

The BoolQ and BFCL data files have now been corrected; see `data/supervision_provenance.json`. A separate v2 adapter has completed training. On 40 local BFCL-derived single-tool test examples, it selected the correct tool in all 40 original and all 40 permuted menus; two test queries exactly overlap training queries, and the probe does not score argument correctness or the official BFCL task. In a repeated three-case API probe, atomic and explicit-numeric calls were 5/5 each, while free-text email calls were 0/5. The numeric value was deterministically extracted from the user text, not generated by the model. Editing data does **not** repair v1 weights or old results. Historical Pareto figures mix measurements with inserted estimates and are not paper evidence. [RESULTS.md](RESULTS.md) identifies which numbers were measured and which were not.

## Run locally

A CUDA-capable machine with a substantial memory budget is required for the BF16 checkpoint.

~~~bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# Set DIFFUSION_GEMMA_PATH and REFLEX_LORA_PATH in .env.
python -m src.server
~~~

The server defaults to port 8090 and exposes `/health`, `/v1/models`, and `/v1/chat/completions`. Example request:

~~~bash
curl http://127.0.0.1:8090/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"reflex-diffusiongemma","messages":[{"role":"user","content":"Mute audio"}],"tools":[{"type":"function","function":{"name":"mute_audio","description":"Mute system audio","parameters":{"type":"object","properties":{},"required":[]}}}]}'
~~~

Responses include `reflex_metadata` with path, tier, engine time, and pass count. Check the selected tool and its arguments: HTTP 200 and valid JSON do not imply a correct action. Streaming currently starts after complete generation.

## Reproduce and evaluate

- `python scripts/prepare_datasets.py --verify-splits` checks split overlap. `--repair-existing-supervision` reproduces the label correction. The BFCL data here is a **single-call routing subset**, not the official full BFCL score.
- `python experiments/train_reflex_lora.py` trains a decoder LoRA adapter into `models/reflex_lora_v2` by default, preserving v1. It primarily trains one-slot classification, not a complete text sampler or tool-argument model.
- `python -m unittest discover tests/` runs fast code-level tests. GPU integration scripts in `tests/` must be run separately.
- `python experiments/benchmark_routing_v2.py` tests held-out BFCL routing and candidate-order permutations through the API, retaining per-item traces.
- `python experiments/benchmark_tiered_latency.py` records correctness and timing together in new timestamped traces. Wrong-route latency is not a Tier-2 or Tier-3 success.

For a paper, the project still needs an independent larger routing test set, learned argument and free-text tool outputs, nonzero statistically controlled exit coverage, full-path generation quality, measured end-to-end latency at matched quality, uncertainty estimates, and strong baselines. The [Google model guide](https://developers.googleblog.com/diffusiongemma-the-developer-guide/) and [official generation documentation](https://huggingface.co/docs/transformers/en/model_doc/diffusion_gemma) describe the base model. A [vLLM structured-read prototype](https://github.com/vllm-project/vllm/pull/57250) already demonstrates short seeded canvases and one-step decisions, so novelty must be stated modestly and supported by comparisons.
